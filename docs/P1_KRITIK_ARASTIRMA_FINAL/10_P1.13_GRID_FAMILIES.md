## 8. Time, ambiguity, EOF, gap, duplicate, late event
Historical economic ordering uses event/bar/effective time, not processing time. Ambiguity cannot invent a suffix; only committed prefix survives. EOF is an explicit outcome rather than an implicit fill. Known duplicate is idempotent; conflicting duplicate becomes CONFLICT; genuinely new late event enters reconciliation/recovery. Feed/data gaps are explicit STALE/GAP/INDETERMINATE states unless a versioned repair transform exists.

## Arithmetic/geometric generation
Binance documents arithmetic equal difference and geometric equal ratio [S28].
- arithmetic: `delta=(U-L)/N`; level_i=`L+i*delta`.
- geometric: `r=(U/L)^(1/N)`; level_i=`L*r^i`.
`N` convention (interval vs order count) must be profile field; off-by-one test required.

## Inventory conservation
Each accepted grid sell must consume owned/position capacity; each accepted buy increases inventory. Pending replacement orders do not create inventory. Grid profit (matched cycle realized profit) != total equity (includes inventory mark-to-market and fees).

## Trailing/infinity/reverse
Binance trailing-up shifts grid and cancels/replaces levels [S29]. This is behavior discovery only. **DEFER:** infinity/reverse grid until each variant’s exact boundary, inventory and replacement semantics separately specified.

## Leveraged grid
Must use P1.12 futures margin engine and P1.11 shared account; spot grid formulas cannot be reused. **REJECT** single grid engine that just adds leverage parameter.

## Partial fill/replace
Replacement only after accepted fill/cancel lifecycle coverage. Known duplicate does not spawn duplicate replacement level.

## Decision
Arithmetic/geometric level generation **ACCEPT**; leveraged/trailing variants **CONDITIONAL/DEFER** with separate profile and tests.
