## 7. Asset/unit/precision/rounding
Economic inputs are parsed from decimal strings or exact integers. Internal arithmetic may use Decimal/Fraction; venue quantization occurs at the declared order/fee/margin boundary, never at UI formatting. Asset/unit tags are mandatory for qty, notional, fee, funding, margin and reserve. Rounding mode is part of the model/profile identity; missing rounding owner fails closed.

## 8. Time, ambiguity, EOF, gap, duplicate, late event
Historical economic ordering uses event/bar/effective time, not processing time. Ambiguity cannot invent a suffix; only committed prefix survives. EOF is an explicit outcome rather than an implicit fill. Known duplicate is idempotent; conflicting duplicate becomes CONFLICT; genuinely new late event enters reconciliation/recovery. Feed/data gaps are explicit STALE/GAP/INDETERMINATE states unless a versioned repair transform exists.

## 9. Core/API contract etkisi
Core owns acceptance and economic mutation. API returns typed exact numeric strings, explicit state/result taxonomy, model/profile/version/hash identities, and source/effective times. API must not expose a display-formatted value as economic authority. Unsupported/unknown/blocking fields remain tagged, not numeric zero.

## 10. Persistence/replay/hash etkisi

## 1. Netting vs hedge
Bybit current position-mode docs: one-way mode same contract için tek direction taşır; opposite order önce mevcut position’u azaltabilir. Hedge mode simultaneous long+short taşımayı destekler [S24]. **Conclusion:** position identity must include `position_mode` and hedge side where applicable.

Suggested keys:
- one-way: `(account, venue_profile, symbol)` -> signed/net qty;
- hedge: `(account, venue_profile, symbol, LONG)` and `(…, SHORT)` separate.

Do not auto-net hedge-mode economic ledgers for fee/funding attribution. UI net exposure ayrı derived metric olabilir.

## 2. Reduce-only / close semantics
Bybit reduce-only order current position’u artırmamayı amaçlar ve qty’yi position size’a göre azaltabilir [S25]. Bu semantic venue-specific’tir. Core independent invariant: exit intent accepted olsa bile accepted fill open risk’i artırmamalı; aksi `REJECT/CONFLICT`.

## 4. Two-leg lifecycle
A strategy with two separate orders does **not** have exchange-level atomicity unless venue provides a native atomic multi-leg contract (not established here). Therefore local state must model exposure between legs:

```text
PLANNED
 -> LEG_A_SENT / LEG_B_SENT
 -> ONE_LEG_FILLED
 -> PARTIAL_HEDGE
 -> BOTH_LEGS_FILLED
 -> BALANCED
 -> EXITING
 -> COMPLETED
 failure: TIMEOUT / LEG_REJECTED / ONE_LEG_LIQUIDATED / RECOVERY_REQUIRED
```

`ONE_LEG_FILLED` is a first-class economic state, not an impossible intermediate. Accepted first-leg fill must persist even if second leg later fails.

## 5. Sequencing/timeout
- sequential model: second leg intent created only after first accepted fill; maximizes certainty, increases exposure latency.
- parallel model: both intents active; reduces latency, increases independent fill/partial risk.
- timeout based on event/effective time; wall-clock simulation policy separated.
There is no universal superior choice; **CONFIG/CONDITIONAL**.

## 6. Partial hedge
Define exposure in common risk unit. For same-underlying linear legs, `net_delta_qty = signed_qty_A + signed_qty_B` may be useful, but cross-product multiplier/FX requires conversion profile. Unknown conversion -> `INDETERMINATE`, not zero.

## 7. Spread/funding/borrow/transfer/fees
Separate ledgers per leg and per event. Spread is valuation difference, not fee. Funding applies only derivative leg at funding timestamps [S17]. Spot borrow/transfer only if such product explicitly modeled; do not infer.

## 8. One-leg liquidation
Liquidation is an accepted venue event in that leg; other leg remains. Strategy becomes `RECOVERY_REQUIRED` and recomputes risk from surviving exposure. Do not auto-close survivor unless explicit policy creates a new exit order and it fills.

## 9. Atomicity/recovery
Persistence atomicity applies per accepted event and resulting two-leg aggregate state. It does not invent cross-venue atomic execution. Crash after leg A fill before leg B intent must replay to exactly `ONE_LEG_FILLED`; retry must not duplicate leg A.

## 10. Independent oracle
Oracle tracks each leg separately then computes aggregate exposure. It imports no production reducer. Fixtures include: A filled/B open; A partial/B full; duplicate A fill; B reject; one-leg liquidation; restart at every intermediate state.
