## 7. Asset/unit/precision/rounding
Economic inputs are parsed from decimal strings or exact integers. Internal arithmetic may use Decimal/Fraction; venue quantization occurs at the declared order/fee/margin boundary, never at UI formatting. Asset/unit tags are mandatory for qty, notional, fee, funding, margin and reserve. Rounding mode is part of the model/profile identity; missing rounding owner fails closed.

## 8. Time, ambiguity, EOF, gap, duplicate, late event
Historical economic ordering uses event/bar/effective time, not processing time. Ambiguity cannot invent a suffix; only committed prefix survives. EOF is an explicit outcome rather than an implicit fill. Known duplicate is idempotent; conflicting duplicate becomes CONFLICT; genuinely new late event enters reconciliation/recovery. Feed/data gaps are explicit STALE/GAP/INDETERMINATE states unless a versioned repair transform exists.

## 9. Core/API contract etkisi
Core owns acceptance and economic mutation. API returns typed exact numeric strings, explicit state/result taxonomy, model/profile/version/hash identities, and source/effective times. API must not expose a display-formatted value as economic authority. Unsupported/unknown/blocking fields remain tagged, not numeric zero.

## 10. Persistence/replay/hash etkisi
Persist event identity, economic payload, ordering/effective time, model/config/dataset/kernel/schema/canonicalization versions, and resulting state version. Replay must be deterministic under the same identity tuple. Canonical hash supports comparison but is not the only oracle; field-level independent comparison is required.

## 11. UI/UX ve yanlış yorum riski

## 1. Time split
Chronological split zorunludur. scikit-learn `TimeSeriesSplit` future data ile geçmişi değerlendiren ordinary CV’yi uygunsuz sayar ve train-test arasında configurable `gap` sunar [S31].

Supported window families:
- expanding: train başlangıcı sabit, sonu ilerler;
- rolling: sabit-length train penceresi ilerler;
- anchored validation + untouched final holdout.
Seçim model identity’ye dahil edilir.

## 2. Leakage
Look-ahead, future-known values veya retroactively adjusted data’yı present decision’da kullanmaktır; QuantConnect research guidance point-in-time data ve reporting lag önemini vurgular [S34]. Indicator warm-up gerçek trade window’dan önce state hazırlamak için kullanılabilir; warm-up döneminde trading yapılmamalıdır [S35].

### Purge / embargo
`gap` kavramı verified [S31]. Finansal label’ların geleceğe taşan horizon’ları varsa train/test boundary çevresinde overlapping information kaldırılmalıdır. Exact purge/embargo length = max(feature lookback dependency, label future horizon, event settlement horizon) gibi local data-construction bilgisine bağlıdır; **LOCAL_CODE/DATA_REQUIRED**. Sabit “N bar” uydurulmaz.

## 3. OOS freeze rule
**ACCEPT:** OOS sonuç görüldükten sonra tuning yapılırsa aynı segment artık untouched final evaluation değildir. Bu mantıksal olarak model selection’ın eval data’dan bilgi almasıdır ve selection bias/backtest overfitting riskine girer [S32][S33]. Yeni tuning sonrası yeni untouched holdout veya açıkça “validation reused” etiketi gerekir.

Exceptions: result yalnız operational bug düzeltmesi nedeniyle invalidated ise eski OOS “performance evidence” olarak kullanılmaz; rerun yeni evaluation lineage’dır.

## 4. Multiple testing
Bailey/López de Prado DSR, çok sayıda deneme arasında en iyi sonucu seçmenin performans beklentisini şişirdiğini açıklar [S32]. Her optimization study için `trial_count`, parameter search space, objective, selection rule ve rejected runs saklanmalıdır. “Sadece kazanan run” export **REJECT**.

## 5. Run comparison
Compare only when dataset/config/model/kernel/seed policy identities compatible. Failed/dropped/invalid runs denominator’dan sessizce çıkarılamaz; selection protocol record’unda görünür. OOS ve in-sample KPI ayrı columns/objects.

## 6. Determinism
Randomness varsa seed ve RNG/version sakla. External nondeterminism (unordered iteration, wall clock, network data) historical kernel’a girmemeli. Same canonical inputs -> same event ledger/result hash.

## 7. Stress model
Stress normal backtest değildir. Scenario dimensions:
- spread widening;
- slippage (constant/volume share gibi explicit model [S13]);
- latency;
- volume participation;
- partial fill;
- OHLC ambiguity;
- missing/gap data;
- best/worst-case paths.

Each stress run stores base-run identity + stress-profile hash. UI label `STRESS`, not “Backtest Result”.

## 8. Data-quality gate
Before run:
- timestamps strictly nondecreasing per stream (duplicates policy explicit);
- timezone canonical;
- OHLC invariant `low <= open,close <= high`;
- nonnegative volume unless dataset says otherwise;
- missing bars/gaps catalogued, not silently forward-filled;
- symbol/contract specification version boundaries recorded;
- adjusted/raw data type explicit.

Failure -> `INVALID_INPUT` or `INDETERMINATE`, not auto repair unless repair transform itself versioned and hashed.

## 9. Test matrix acceptance
- future row mutation cannot change earlier decisions;
- warmup events cannot create fills;
- OOS seen + retune -> prior OOS lineage flag changes to `TOUCHED`;
- gap/purge fixtures prove no overlapping label horizon;
- trial register count preserved;
- stress results cannot overwrite normal result;
- same run replay hash identical.

## 10. Decision
Chronological WF/OOS freeze/deterministic identity/multiple-test registry **ACCEPT**. Exact purge/embargo length **LOCAL_DATA_REQUIRED**. DSR or other statistical metric mandatory production gate **DEFER**; use as diagnostic, not universal truth.
