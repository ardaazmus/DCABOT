## 7. Asset/unit/precision/rounding
Economic inputs are parsed from decimal strings or exact integers. Internal arithmetic may use Decimal/Fraction; venue quantization occurs at the declared order/fee/margin boundary, never at UI formatting. Asset/unit tags are mandatory for qty, notional, fee, funding, margin and reserve. Rounding mode is part of the model/profile identity; missing rounding owner fails closed.

## 8. Time, ambiguity, EOF, gap, duplicate, late event
Historical economic ordering uses event/bar/effective time, not processing time. Ambiguity cannot invent a suffix; only committed prefix survives. EOF is an explicit outcome rather than an implicit fill. Known duplicate is idempotent; conflicting duplicate becomes CONFLICT; genuinely new late event enters reconciliation/recovery. Feed/data gaps are explicit STALE/GAP/INDETERMINATE states unless a versioned repair transform exists.

## 9. Core/API contract etkisi
Core owns acceptance and economic mutation. API returns typed exact numeric strings, explicit state/result taxonomy, model/profile/version/hash identities, and source/effective times. API must not expose a display-formatted value as economic authority. Unsupported/unknown/blocking fields remain tagged, not numeric zero.

## Trigger != execution
Bybit TP/SL ve trailing dokümanları trigger sonrasında close order üretildiğini gösterir [S26][S27]. Bu nedenle trigger yalnız state/event; accepted fill gelmeden position/PnL mutate edilmez.

## Multi-TP quantity conservation
`initial_exit_capacity = open_position_qty`. Accepted exit fills + still-committed exits + free exit capacity hiçbir zaman open position’u aşmamalı. Partial TP/SL ürünleri birden fazla qty seviyesini destekleyebilir [S26]; local model competing exits’i OCO/cancel policy ile yönetmelidir.

## Stop/limit/market
- stop = trigger condition;
- stop-market = trigger sonrası market execution candidate; gap/slippage mümkündür;
- stop-limit = trigger sonrası limit order; fill guarantee yok;
- limit TP = price constraint, trigger’den farklıdır.
QuantConnect fill models bu ayrımı açıkça farklı condition/price kurallarıyla modeller [S11][S12].

## Trailing
State: `INACTIVE -> ARMED -> ACTIVE(reference_extreme, stop_price) -> TRIGGERED -> EXIT_ORDER -> FILLED/OPEN_AT_END`.
Ratchet invariant: long exit trailing stop fiyatı favorable movement boyunca düşmez; short exit için yükselmez. Bybit trailing stop favorable price’i takip edip belirli retracement sonrası market order tetikler [S27].

## Breakeven
Naive `entry_price` hedefi fee-aware breakeven değildir. Fee-aware target, position cost + already-paid fees + expected exit fee + funding allocation’ını kapatacak exact price’tır. Fee asset farklıysa explicit conversion gerekir; conversion yoksa `NOT_VERIFIED`.

## Cancel-replace/late fill
Old exit cancel request gönderildi diye capacity hemen yeni order’a verilmez; accepted cancel/final coverage beklenir. Late fill gelirse conflicting exit capacity kontrol edilir ve automatic over-close engellenir. Reduce-only venue semantics bunu yardımcı koruma olarak sunabilir [S25], core invariant’ın yerine geçmez.

## Decision
Trigger/execution split, quantity conservation, trailing ratchet **ACCEPT**. Exact fee-aware breakeven venue fee asset ve conversion profile olmadan **CONDITIONAL**.
