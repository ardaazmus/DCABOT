## 7. Asset/unit/precision/rounding
Economic inputs are parsed from decimal strings or exact integers. Internal arithmetic may use Decimal/Fraction; venue quantization occurs at the declared order/fee/margin boundary, never at UI formatting. Asset/unit tags are mandatory for qty, notional, fee, funding, margin and reserve. Rounding mode is part of the model/profile identity; missing rounding owner fails closed.

## 8. Time, ambiguity, EOF, gap, duplicate, late event
Historical economic ordering uses event/bar/effective time, not processing time. Ambiguity cannot invent a suffix; only committed prefix survives. EOF is an explicit outcome rather than an implicit fill. Known duplicate is idempotent; conflicting duplicate becomes CONFLICT; genuinely new late event enters reconciliation/recovery. Feed/data gaps are explicit STALE/GAP/INDETERMINATE states unless a versioned repair transform exists.

## 9. Core/API contract etkisi
Core owns acceptance and economic mutation. API returns typed exact numeric strings, explicit state/result taxonomy, model/profile/version/hash identities, and source/effective times. API must not expose a display-formatted value as economic authority. Unsupported/unknown/blocking fields remain tagged, not numeric zero.

## 10. Persistence/replay/hash etkisi
Persist event identity, economic payload, ordering/effective time, model/config/dataset/kernel/schema/canonicalization versions, and resulting state version. Replay must be deterministic under the same identity tuple. Canonical hash supports comparison but is not the only oracle; field-level independent comparison is required.

## 11. UI/UX ve yanlış yorum riski
UI renders backend-authoritative values and state labels. It must distinguish OPEN_AT_END/INDETERMINATE/STALE/CONFLICT from completed-valid results, and must not silently hide missing data or recompute PnL/reserve/risk. Risk severity cannot rely on color alone in accessibility-sensitive views.

## Accessibility
WCAG 2.2 reflow requires content usable at width equivalent to 320 CSS px without two-dimensional scrolling except necessary content [S38]. Keyboard focus and visible focus criteria apply.

Acceptance:
- all controls keyboard reachable;
- focus order logical and focus visible;
- error/risk state not color-only; icon/text/state code used;
- screen-reader accessible labels and status changes;
- 320px view: core controls/data remain available; wide tables may use justified two-dimensional exception but alternate summary should exist where practical;
- grayscale test preserves severity meaning.

## Financial display boundary
UI receives exact API strings and formatting metadata. It may format locale/grouping, but may not recalculate PnL, reserve, margin, liquidation, qty remainder. Display rounding never sent back as economic source.

## Explicit states
`EMPTY`, `LOADING`, `ERROR`, `STALE`, `INDETERMINATE`, `CORRUPT`, `OPEN_AT_END` distinct. Do not render unknown as zero or green success.

## Themes
Dark/light theme must preserve contrast and semantic non-color cues. No new financial meaning tied only to palette.

## Windows offline
Microsoft documents packaged/unpackaged/self-contained deployment options and MSIX [S39]. Disconnected MSIX packaging tooling has explicit offline package/license/FOD constraints [S40]. For LOCAL_SIMULATOR, installer choice is stack-dependent; acceptance requires clean offline VM installation/startup, no credential/network requirement for historical mode, deterministic local data path migration, uninstall/upgrade test.

No visual design decision is assumed here. If design benchmarking is later needed: anonymously collect screenshots of state-heavy desktop analytics UIs focusing only on accessibility/layout patterns; do not copy proprietary visual identity.
