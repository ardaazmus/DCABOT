## 6. Matematiksel model
| Formula | Unit/scope | Failure/oracle |

No formula may combine different assets/units without an explicit conversion event/rate/source. Venue-specific margin/liquidation is BLOCKED when its profile is absent.

## 7. Asset/unit/precision/rounding
Economic inputs are parsed from decimal strings or exact integers. Internal arithmetic may use Decimal/Fraction; venue quantization occurs at the declared order/fee/margin boundary, never at UI formatting. Asset/unit tags are mandatory for qty, notional, fee, funding, margin and reserve. Rounding mode is part of the model/profile identity; missing rounding owner fails closed.

## 8. Time, ambiguity, EOF, gap, duplicate, late event
Historical economic ordering uses event/bar/effective time, not processing time. Ambiguity cannot invent a suffix; only committed prefix survives. EOF is an explicit outcome rather than an implicit fill. Known duplicate is idempotent; conflicting duplicate becomes CONFLICT; genuinely new late event enters reconciliation/recovery. Feed/data gaps are explicit STALE/GAP/INDETERMINATE states unless a versioned repair transform exists.

## 9. Core/API contract etkisi
Core owns acceptance and economic mutation. API returns typed exact numeric strings, explicit state/result taxonomy, model/profile/version/hash identities, and source/effective times. API must not expose a display-formatted value as economic authority. Unsupported/unknown/blocking fields remain tagged, not numeric zero.

## 10. Persistence/replay/hash etkisi
Persist event identity, economic payload, ordering/effective time, model/config/dataset/kernel/schema/canonicalization versions, and resulting state version. Replay must be deterministic under the same identity tuple. Canonical hash supports comparison but is not the only oracle; field-level independent comparison is required.

## 11. UI/UX ve yanlış yorum riski

## 1. Kapsam ve temel karar

P1.07’nin ana kararı: **accepted FILL tek ekonomik execution authority’dir.** `ORDER_FINAL` order-coverage/lifecycle authority olabilir; candidate veya touch ekonomik mutation değildir. FIX’in ExecutionReport modelinde current order state (`OrdStatus`) ile execution-report purpose (`ExecType`) ayrıdır [S01]; `LeavesQty` aktif order için `OrderQty-CumQty` olarak tanımlanır [S02].

## 2. Order lifecycle

Önerilen local-neutral state-machine:

```text
INTENT -> OPEN
OPEN --accepted partial FILL--> PARTIALLY_FILLED
PARTIALLY_FILLED --accepted FILL, cum<orig--> PARTIALLY_FILLED
OPEN/PARTIALLY_FILLED --accepted FILL, cum==orig--> FILLED_QUANTITY
FILLED_QUANTITY --valid lifecycle coverage--> ORDER_FINAL(FILLED)
OPEN/PARTIALLY_FILLED --cancel ack--> ORDER_FINAL(CANCELED)
OPEN/PARTIALLY_FILLED --EOF without terminal event--> OPEN_AT_END
any --unresolvable source gap/conflict--> INDETERMINATE/CONFLICT
```

`FILLED_QUANTITY` burada local explanatory intermediate’tır; FIX `Filled` terminal status kullanabilir [S04], fakat araştırma promptunun “full quantity fill != final coverage” şartını korumak için core’da quantity invariant ile external coverage ayrı tutulmalıdır. Mevcut local enum’un aynen böyle olduğu **iddia edilmez**.

### Quantity invariant
Aktif order: `original_qty = cumulative_filled + leaves_qty` [S02]. Terminal remainder ayrıca modelleniyorsa:
`original_qty = cumulative_filled + leaves_qty + explicit_terminal_remainder`.
Terminal canceled/expired state’te FIX LeavesQty 0 olabileceğini söyler [S02]; bu yüzden “unfilled terminal remainder” ayrı audit field olmalıdır, LeavesQty’ye zorlanmamalıdır.

## 3. Reserve / commitment lifecycle

### Kaynak karşılaştırması
- Spot açık order: Coinbase, open order funds’un hold edildiğini ve order executed/canceled olana kadar available balance’dan çıktığını belirtir [S10].
- Derivatives: Bybit order cost; initial margin + estimated fees bileşenleriyle settlement asset’e bağlıdır [S23].
- Spot fee: fee asset purchased crypto olabilir; unfilled/canceled kısım için fee yoktur [S14].

**Sonuç:** tek evrensel `reserve` formülü yok. Spot balance hold, derivatives order margin/cost ve generic risk capacity ayrı reserve profiles olmalıdır.

### Kararlar
| Soru | Karar | Gerekçe |
|---|---|---|
| Candidate reserve mutate eder mi? | REJECT | candidate execution değildir |
| Equality observation reserve mutate eder mi? | REJECT | observation authority değil |
| INTENT reserve? | CONDITIONAL | explicit policy ise; spot/derivatives farkı |
| ACTIVE/accepted placement reserve? | ACCEPT as policy | open order commitment için uygun boundary |
| FILL reserve reduction? | ACCEPT | accepted consumed commitment azaltır |
| Cancel release? | ACCEPT after accepted cancel/final event | pre-ack candidate cancel release yok |
| EOF release? | REJECT by default | EOF venue cancel değildir |
| `NONE` = numeric 0? | REJECT | semantic absence ile measured zero farklı |
| fee reserve içinde? | CONDITIONAL | venue/order-cost profile’a göre |
| `initial_margin_estimate == reserve` | LOCAL_CODE_REQUIRED | local meaning görülmeden eşitlenemez |

### Suggested commitment algebra (generic profile)
`commitment_original` ve `commitment_remaining` aynı unit’tedir. Accepted fill miktarı quote reserve tüketiyorsa conversion function açık olmalıdır.

`remaining = max(0, original_commitment - accepted_consumption - accepted_release)`

Bu generic bookkeeping formülüdür; `accepted_consumption` hesaplama yöntemi profile-specific’tir. Fee başka asset ise implicit conversion yapma; ayrı fee liability veya explicit FX conversion event kullan.

## 4. Historical OHLCV execution

### Placement bar
QuantConnect fill model order timestamp ile aynı/stale barı fill etmemeyi look-ahead önlemi olarak kullanır [S11][S12]. **ACCEPT default:** placement bar eligible değil; `eligible_from = first bar strictly after order effective_time` (unless strategy explicitly models intrabar sub-events).

### Equality vs strict penetration
Kaynaklar tek bir evrensel kural vermez: QuantConnect equity limit buy `low < limit`, sell `high > limit`; stop market tarafında `>=`/`<=` kullanır [S11]. Latest-price model de limit için strict inequality kullanır [S12].

**ACCEPT as explicit simulator policy:**
- LIMIT conservative OHLC profile: equality = Observation, strict penetration = Candidate.
- STOP trigger profile: equality allowed if chosen policy says `>=/<=`; execution still separate.
Bu venue truth değil, versioned fill-model contract’tır.

### Gap/open fill price
QuantConnect equity model buy limit için `min(open, limit)`, sell limit için `max(open, limit)`; stop market için adverse gap yönünde `max(open,stop)+slippage` / `min(open,stop)-slippage` uygular [S11]. **SIMPLIFY:** off
